# MiniMax H3 提示词增强器（T8）

依据固定版本的 MiniMax H3 官方 `h3-prompt-writing` Skill，把用户创意和已连接的图像、视频整理成可直接用于 H3 的提示词文本。

## 使用要点

- **Hybrid 混合模式**：首帧和/或尾帧＋至少一个额外参考图/视频。每槽单图，最多 9 张额外图＋2 张关键帧、3 个视频；按首帧→尾帧→参考图编号，视频独立编号。额外参考不自动充当首尾帧，不分析音轨。
- Hybrid 输出六段参考格式，支持四渠道、本地视觉 GGUF 与 Relay；旧五种任务、默认值、38 个保存字段不变。Quality 检查不了真实像素/视频事实，需人工核对；不代表下游生成服务取消资源限制。
- 只填写“视频创意 / 提示词”即可运行；任务类型、时长、镜头数量会共同约束结果。
- 云端渠道可接收完整视频；本地 GGUF 只读取按真实时间戳采样的画面，不读取视频音轨。
- 本地模型与 mmproj 放在 `ComfyUI/models/LLM` 或任意子目录；节点可重新扫描、自动配对投影器，并复用已安装的 llama-cpp-python。
- API Key 可从 STRING 接口接入，也可使用节点内遮罩输入；接线值优先。
- “MiniMax 官方创意预设”来自官方 Skill；“非官方模板”是 T8/社区 Creative DNA，二者权威边界不同。
- 模板 GIF 只供人类预览，不会发送给 LLM，也不会作为图像或视频参考素材。
- “恢复上次云端结果（不重新生成）”只读取当前进程中本节点的完整内存结果，不会重新调用 API；残缺流或零字节响应不会伪装成成功。
- 云端与本地都会在官方 Skill 后再次锁定所选输出语言；只有完整结果明显跑错语种时才追加一次只纠正语言的请求，网络结果未知时不会重投。云端流始终按 UTF-8 原始字节解码，避免网关错误字符集造成中文乱码。
- **时间线分段**按已完成提示词自己的 `[Shot N] At HH:MM.SSS` 时间线分组，使用“分段数（1=不分段） / Segments”（1–10，默认 1，总时长上限 3600 秒）与“分段方式 / Split mode”（`平均分段（按分段数） / Even` 或 `镜头对齐分段（不切镜头） / Shot-aligned`）。分段只在本地处理已有文本：不追加模型请求、不翻译、不新增事实。
- 每个分段都是独立完整的 H3 提示词：保持该任务类型的原有字段结构，只按本段重新编号 `[Shot N]` 与 `(Sx)`，时间线从 `00:00.000` 开始并保留本段镜头之间的原有间隔。`h3_segments_json` 逐段给出起止秒数、镜头与说话人映射和备注；`h3_segments_text` 用 `===== T8 SEGMENT 1/2 | 0.000-10.000s | 2 shots =====` 开头接该段完整提示词。已完成提示词的 `[Shot 1]` 若写作 `At 00:00.000`（半角或全角逗号都接受），与没有时间码是同一时刻：该写法会被接受，且不会出现在任何分段里；首镜头落在其它时间则以 `"status": "not_split"` 说明原因。`h3_segments_preset` 把同样的分段写成参考预设文件那种 `minimax-h3-timeline-preset` 文档：每条只带该段自己的提示词，`images` 与 `audios` 留空，`startFrame`/`endFrame` 是按该预设的 24 fps 推算的占位值——每段 240 帧（10 秒），后一段比前一段的结束提前 24 帧开始。该文档保留参考预设的采样与时间线字段，画布按本节点默认写为 768×768，其 `selection` 与 `canvas.generation_seconds` 描述第一段；这些帧数只是给预设编辑器用的占位数字，不是成片的实际测量。
- 默认 1 时三个分段输出留空，`enhanced_prompt` 逐字不变。平均分段保持等分边界，可能让一段在镜头中途结束，需要镜头完整时改用镜头对齐分段；I2VA / FL2VA / L2VA 的中间段不承载关键帧，因此没有对齐首行，只能作为续接片段。无法按时间线切分时节点不失败：原提示词照旧返回，`h3_segments_json` 以 `"status": "not_split"` 说明原因。

主要输出为 `enhanced_prompt` STRING，另有原 Relay global/local/time/length/report 端口。Hybrid 模式也保持这些端口与时间规则；padding 只保持已完成尾态。Off 时非空正文只在识别到完整官方字段后重排；Check/Repair 失败保留完整稿并报告，不伪装成通过。
